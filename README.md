# ITSM-бот

Внутренний service desk на одного исполнителя. Сотрудник пишет боту в Telegram
свободным текстом — бот заводит заявку с номером, кладёт карточку в закрытую группу
исполнителя и уведомляет заявителя о смене статуса.

Требования к продукту, модель данных и решения с основаниями — в [`TODO.md`](TODO.md).
Правила работы с кодом — в [`CLAUDE.md`](CLAUDE.md).

## Что нужно

- Python 3.11 или новее
- Токен бота от [@BotFather](https://t.me/BotFather)
- Закрытая группа Telegram, в которой бот — администратор

Группа, а не канал: в канале у поста нет автора, и вопрос исполнителя не с чем
связать (решение D9 в `TODO.md`). Права администратора нужны, чтобы бот мог править
карточку при смене статуса.

## Установка

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"    # Windows
# .venv/bin/python -m pip install -e ".[dev]"          # Linux
```

Дальше все команды показаны в windows-раскладке путей. На Linux —
`.venv/bin/python`.

## Настройка

Скопировать `.env.example` в `.env` и заполнить. `.env` в репозиторий не попадает.

| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `QUEUE_CHAT_ID` | да | id группы очереди, отрицательный, вида `-1001234567890` |
| `DEPARTMENTS` | да | отделы для анкеты, через запятую |
| `DB_PATH` | нет | файл БД, по умолчанию `itsm.db` |
| `BUFFER_SECONDS` | нет | окно склейки сообщений, по умолчанию 45 |
| `RATE_LIMIT_PER_HOUR` | нет | заявок в час на сотрудника, по умолчанию 5 |
| `DEDUP_WINDOW_MINUTES` | нет | окно дедупликации, по умолчанию 10 |
| `CARD_TEXT_LIMIT` | нет | символов текста в карточке, по умолчанию 1200 |

Лишние переменные в `.env` запрещены (`extra="forbid"`): опечатка в имени роняет
запуск сразу, а не тихо оставляет значение по умолчанию.

### Как узнать `QUEUE_CHAT_ID`

Добавить бота в группу, написать в неё любое сообщение и прочитать апдейты:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/getUpdates"
```

В ответе взять `message.chat.id` — он отрицательный.

## Запуск

```bash
.venv/Scripts/python.exe -m alembic upgrade head    # миграции
.venv/Scripts/python.exe -m itsm_bot.bot            # бот
```

Миграциям токен не нужен: они читают только `DB_PATH`. Это разделение намеренное —
первое развёртывание и CI применяют схему до того, как появится `.env` с токеном.

Остановка — `Ctrl+C`: буфер склейки и сессия Telegram закрываются корректно.

## Команды

В личной переписке с ботом:

| Команда | Что делает |
|---|---|
| `/my` | открытые заявки сотрудника |
| `/profile` | изменить кабинет и отдел |

В группе очереди:

| Команда | Что делает |
|---|---|
| `/queue` | список незакрытых заявок |
| `/stats` | сводка за период |
| `/ticket <номер>` | полный текст заявки, если он не поместился в карточку |
| `/publish <номер>` | дослать карточку заявки, у которой её нет |

Статус меняется кнопками на карточке, а не командой. `/publish` нужен для редкого
случая, когда заявка записалась в БД, а отправка карточки не прошла: бот сообщает о
таких заявках при старте. Досылка ручная намеренно — автоматическая удвоила бы
карточку в окне между отправкой и записью `queue_message_id`.

## Как это устроено

```
Telegram → буфер склейки (45 с) → repo.create_ticket (маскирует) → SQLite
        → карточка в группу очереди → кнопки статуса → уведомление заявителю
```

Два свойства, которые важно не сломать:

**Сырой текст обращения нигде не сохраняется.** Маскирование живёт внутри слоя
хранения (`storage/repo.py`), и дальше идёт только замаскированная строка — в БД, в
группу, в логи. Отдельного хранилища оригиналов нет по замыслу.

**Подряд идущие сообщения одного человека — одна заявка.** В личку пишут очередями
(«Здравствуйте» → «принтер» → «не печатает»), поэтому сообщения собираются в буфере
и превращаются в заявку через 45 секунд после последнего.

## Бэкап

Файл БД (`DB_PATH`) копируется ежедневно, хранится 30 дней — требование N7 в
`TODO.md`. Это операция уровня виртуальной машины, в коде бота её нет.
